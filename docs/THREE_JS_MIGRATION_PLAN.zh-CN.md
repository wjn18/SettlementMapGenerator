# 城镇生成器从 Blender 到 Three.js 的移植方案

建议把线上三维做成现有地图工坊的一个视图。用户生成或导入城镇后，点「三维」就能从同一份规划看到建筑、街道和水系，旋转、缩放并导出当前取景的 PNG。Netlify 托管网页、脚本和精选模型，浏览器组装并绘制场景。Blender 继续用于制作素材、生成美术参考和复核旧结果。这样发布新版本时，构建机和访问者都无需安装 Blender。

**建议先投入 11–17 人日完成可部署的内陆河城试点，再决定是否投入完整移植。** 全量预计 40–60 人日，包含试点。最大的工作量在建筑适配、河海与桥港的几何校验，以及把静态插画改成转动时仍清晰的实时画面。继续使用现有规划、语言、前端和托管平台，可以单独验证这些工作。

## 现有基础与迁移边界

| 现有能力 | 迁移动作 |
| --- | --- |
| TypeScript 核心已经输出 `TownData`。生成、导入、二维显示都能得到当前地图的实体与坐标 | 直接读取网页当前快照，复用序列化、校验和塔楼筛选逻辑。用户切视图时使用正在看的城镇，表单里尚未提交的参数不参与 |
| Blender 适配器展开顶点 ID、道路宽度、建筑轮廓、墙段和门洞，Python 再拼装并检查实际网格 | 抽取能在浏览器运行的纯数据变换，将依赖 Blender 的几何规则逐项移植为 TypeScript。保留 Python 版作对照 |
| 三维面板目前提交本地任务、每 2.5 秒查询状态，最终显示图片。现有 Netlify 构建只发布静态目录 | 生产三维面板直接驱动画布。本地开发环境保留旧图片任务与历史入口。二维页面按现有方式启动 |
| 现有三维交付分为 1500 / 3200 像素、城内 / 全景 / 城堡取景。模型文件由后台保管 | 浏览器保留图片导出和取景能力。上线前确认哪些素材可以发给浏览器。即便界面仅提供 PNG，加载到客户端的几何和纹理仍可被取得 |

若产品硬性要求模型几何保密，或要求用户关页后服务器继续批量出图，应保留独立的云端渲染任务，由服务器只返回图片。该部署有运行与存储成本，应独立估算。以下排期按**浏览器实时渲染、精选素材可随站点发布、无需跨设备任务历史**编制。[现有三维使用说明](../README.md#从网页生成三维) · [数据结构](../packages/core/src/types.ts) · [当前面板](../apps/playground/src/three-d.ts) · [部署配置](../netlify.toml)

## 代码和数据如何衔接

1. **接入当前快照。** 沿用 `main.ts` 中的 `createThreeD(() => town)` 接点。进入三维时才动态加载渲染包，记录 `serializeTown(town)` 的哈希、生成器版本和装配版本。导入 JSON 后使用其中的顶点和实体，同一 seed 经不同版本生成可能得到不同地图。[网页入口](../apps/playground/src/main.ts) · [核心导出](../packages/core/src/index.ts)
2. **把规划转成可测试的场景数据。** 建议新增 `packages/renderer-three`，包内分开纯几何装配与 Three.js 显示。装配层输入快照，输出带来源 ID 的顶点、索引、材质分组、重复构件变换和警告，可在 Node 测试或浏览器 Worker 运行。显示层负责上传几何、管理相机、材质和导出。沿用现有二维绘制接口和工作区构建顺序，给三维包加独立构建入口。[现有三维适配器](../experiments/3d-sample/export-minimal-town.mjs) · [现有二维绘制器](../apps/playground/src/renderers.ts)
3. **固定坐标、尺度和朝向。** 以 Blender 三维的默认水平比例 0.5 为首版基准。若以规划中心为原点，规划点 `(x, y)` 和以场景单位表示的高度 `h` 转成 `(0.5 × (x − cx), h, −0.5 × (y − cy))`。道路宽度、码头宽度使用同一水平比例。用不对称建筑、东侧海岸和船头方向验证正反面，GLB 加载后按导出坐标核对安装点，避免重复旋转。[装配入口与比例](../experiments/3d-sample/render_sample_v2.py) · [港口素材坐标约定](../experiments/3d-sample/harbor-assets.md)
4. **保留实体身份和确定性。** 每栋建筑、每段道路、每座桥保留源 ID，合并网格后仍能从三角面范围反查来源。市场陈设与装饰使用按版本、种子和实体 ID 派生的随机序列，加载顺序不影响结果。几何输入须通过现有能力检查，例如旧河图缺少真实河面、缺桥或桥宽不足时，继续提供二维并显示具体原因。[现有河流能力检查](../apps/playground/shared/three-d-support.mjs)
5. **处理取消和换图。** 只有当前快照的装配结果能进入画布。切换地图时取消旧 Worker 或丢弃过期响应，释放上一图独占的几何、材质和渲染目标。复用素材按引用计数释放，避免快速来回切图时黑屏或串图。把「组装几何」「加载素材」「可交互」做成实际进度，失败后可用同一快照重试。

## 城镇各部分怎样移植

| 对象 | 实施方法 | 验收时看什么 |
| --- | --- | --- |
| 建筑、屋顶和立面 | 按真实建筑轮廓生成墙身。移植地块拟合、屋脊和裁切规则。门窗、木构与招牌按立面长度和邻栋净距安装 | 将墙脚反投影回源规划。凹地块、狭长房和相邻建筑均有覆盖。屋顶越界、退化三角面和门窗穿邻栋可定位到建筑 ID。[轮廓几何](../experiments/3d-sample/footprint_geometry.py) · [屋脊规则](../experiments/3d-sample/roof_ridges.py) |
| 道路、墙、城门和塔楼 | 根据中心线和原宽生成铺装，保留非零短段，补齐弯道和路口。沿有效墙段建墙，按源城门留洞，沿用塔楼筛选 | 实际铺装连续，城门净宽可通行。逐段检查墙线与塔位。把已有极短路段回归纳入测试。[路面生成](../experiments/3d-sample/road_surface.py) · [塔位规则](../packages/core/src/wall-towers.ts) |
| 教堂、城堡和市场 | 优先用规划里的教堂角色，旧图沿用已验证的角色推断。主堡和附属建筑适配各自轮廓。每个市场按来源 ID 建地面、放陈设，共享空间避让 | 教堂朝向和主堡入口符合规划。零、单、多市场分别通过。小市场允许记录空间不足，人物和摊位避开城防及桥头。[城堡装配](../experiments/3d-sample/castle_integration.py) · [多市场规则](MULTI_MARKET_IMPLEMENTATION.zh-CN.md) |
| 内陆河与石拱桥 | 从真实河面裁两岸与河槽，按桥的路径、跨距和净宽生成桥面、石拱、栏杆及桥台。桥面在两端回到街道高度 | 两岸各有道路接入，地面不盖河，拱下有实际开口。历史木桥素材保留为旧图对照。[石拱桥算法](../experiments/3d-sample/bridge_geometry.py) · [河流素材说明](../experiments/3d-sample/river-assets.md) |
| 海岸、河口和港口 | 先算统一水陆分区，再放置护岸、码头、船与仓库构件。按实际船体截面裁海面、浅水和水纹。在河港沿用源泊位与进出水路 | 四向海岸、港口开关、海港与河港同图均验证。河口水面无重叠，护岸避开河口。船舱射线可命中舱底，码头入口保留整幅通行宽度。[河口实现](ESTUARY_CITY_IMPLEMENTATION.zh-CN.md) · [河港规则](RIVER_HARBOR_IMPLEMENTATION.zh-CN.md) |

## 素材与线稿淡彩

本工作区四个库合计有 **90 个 GLB，约 15 MiB**。其中小镇 61 个、主堡 6 个、港口 16 个、河流与历史木桥 7 个。这个数是磁盘上 GLB 文件的总大小，实际下载还取决于选用的构件、纹理和压缩。素材位于 Git 忽略的 `artifacts/`。首个交付物应包含可从干净检出构建的精选 Web 素材包。[小镇素材清单](../experiments/3d-sample/small-town-assets.md) · [主堡清单](../experiments/3d-sample/castle-assets.md) · [版本控制排除项](../.gitignore)

- **素材发布。** 首版将获准发布的 GLB、必需纹理和清单放入受版本控制的网页素材目录，按基础、城防、港口分组。清单记录素材 ID、版本、内容哈希、安装点、朝向、允许伸缩轴及外部纹理。构建时检查引用完整。场景需要时才通过 `GLTFLoader` 加载相应组。[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)
- **可变与固定几何。** 地块屋壳、路口、石拱桥跨和水陆裁剪由代码生成。门窗、树、摊位和船等固定网格使用现有 GLB。相同网格与材质按街区实例化，不规则墙体和路面按材质在街区内合并。远景先省略小招牌、窗框与人物，保留房屋轮廓、城防和桥头。[Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)
- **还原画风。** 以 Blender 的正交相机、纸色、石木色板和相同取景为基准。第一轮只画墙顶分界、屋脊、城防外缘、桥券等结构线，隐藏三角剖分边。第二轮加入贴在表面的淡彩纹理、背光排线和柔和阴影。桌面和手机共用色板，手机先减少阴影分辨率、细线与像素比。用全景、沿街和桥头截图及旋转录像审核线宽、亮度、远景噪点与闪烁。[Blender 材质规则](../experiments/3d-sample/illustration_v2.py) · [线稿合成流程](../experiments/3d-sample/render_pipeline.py)

## 用户操作和结果保存

| 操作 | Web 版行为 |
| --- | --- |
| 打开或操作三维 | 桌面拖动旋转、滚轮缩放，触屏单指旋转、双指缩放。默认正交城内取景，提供全景和复位。仅在有城堡时启用城堡取景 |
| 切换二维或生成下一城 | 二维与三维指向同一快照，切回二维保留原视口。生成下一城后清楚显示三维正在更新，旧结果不能覆盖新图 |
| 导出 PNG | 按当前相机单独绘制 1500 或 3200 像素图片，完成后恢复交互分辨率。检测设备渲染目标上限。无法完成高清导出时提供 1500 像素重试，并标明实际尺寸 |
| 保存、分享和刷新 | 沿用地图 JSON 和参数分享。跨版本精确复现以 JSON 为准。纯静态版建议用 IndexedDB 保存近期快照和相机参数，清理浏览器数据会清掉本机记录。刷新时从快照重建，原 Blender 的任务 ID 继续由本地历史入口处理 |
| 浏览器能力或素材异常 | 创建 WebGL 2 上下文失败时回到可用的二维地图。选配装饰加载失败可显示基础场景并标明缺件。关键几何或必需资源失败则提示重试。上下文丢失后从快照恢复或切回二维。[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html) |

## 里程碑与投入

按一名熟悉 TypeScript 和三维图形的工程师主做、现有素材可用估算。以下为工程人日，美术评审与真机借测需配合安排。若一人全职顺序推进，全量约 8–12 个工作周。每阶段都产出可以独立检查的结果。

| 阶段 | 工程人日 | 可交付成果与进入下一阶段的条件 |
| --- | ---: | --- |
| M0 固定基线与素材 | 3–5 | 固定源 JSON、版本、哈希、相机、对照图与结构报告。选出可发布的首批 GLB。在静态预览中加载一栋不对称建筑和一个朝向明确的构件，确认尺度、朝向与材质。记下目标机型 |
| M1 内陆河城试点 | 8–12 | 在现有网页完成切换、旋转、缩放和 1500 像素导出。用石拱桥样片完成普通房屋、道路、两岸及桥。另用有墙快照验城门。试点界面注明已覆盖的地形，以及尚未装配的市场陈设和专用地标。产出静态预览、画面对照、手机记录与缺口清单 |
| M2 建筑与城内细节 | 10–15 | 补齐异形屋顶、教堂、主堡、城防、多个市场与陈设避让。完成城内、全景、城堡取景及桌面高清导出，落实同输入稳定重建，完成美术评审 |
| M3 海岸与港口 | 12–18 | 接入四向海岸、河口、海港、内河港、双港、泊位和船舱排水。通过有港、无港及双港样片的实网格校验与反例测试 |
| M4 大城与发布 | 7–10 | 跑完七档规模、真机预算、异常恢复、历史和下载流程。完成无 Blender 的干净构建、Netlify 预览验收、默认入口切换和回退演练 |

**M1 的决策依据**是同一座真实河城在静态站点上的表现。桥头和城门能否通行、旋转时线稿是否稳定、目标手机能否流畅拖动，三项同时通过再推进 M2。如果几何正确但手机超预算，先用同一快照比较实例化前后、开关阴影与远景装饰的耗时，再调整工期。M2 和 M3 复用 M1 确定的坐标、几何校验和素材契约。

## 样片与验收方法

基线以保存的 `source-town.json` 和对应版本为准。建议从现有本地样片提取少量规划、参考图及预期统计，纳入版本控制的测试夹具。大型原始场景留在离线回归环境。已有的对照资料可从[全规模回归说明](RIVER_CITY_IMPLEMENTATION.zh-CN.md)和[三维测试目录](../tests/three-d)定位。

| 样本 | 用途与明确预期 |
| --- | --- |
| `3d-arch-river-only` | M1 石拱桥主样本。保存的 0.17.0 规划为 170 栋、58 条路、1 座桥、0 个城门。对齐两岸、道路和单桥，以同目录参考图评审画风 |
| `3d-river-town` | M1 兼容样本。0.15.1 规划为 225 栋、97 条路、6 个城门、1 座桥。验证旧图坐标、城门和桥位。该样片的历史木桥图只用于布局对照，当前桥型以石拱桥基准为准 |
| `3d-arch-river-harbor`、`3d-arch-estuary-harbor`、`3d-multi-market` | 检查有墙河港、河口港城和双市场。另覆盖干地、四向海岸、无港、双港、零市场、无城堡，验证能力开关和空数据 |
| `river-all-sizes` | 运行内陆与河口各 6、12、24、40、60、80、100 档，共 14 份历史规划。两份 100 档分别为 2462 与 1668 栋。它们适合测规模和几何覆盖，新增港口规则另用对应新快照验证 |

**结构验收。** 在 Node 验证规划适配与三角化，再从浏览器实际提交的 `BufferGeometry` 索引、顶点与实例变换回读。将墙脚、路面宽度、墙段和桥端逆变换后与源 ID、位置及既有几何容差对照。例如石拱桥主样本的建筑墙脚容差为 0.0001 个规划单位，测试应在逆变换回规划坐标后比较。以实际三角面检查水陆覆盖、桥洞净空和船舱排水。加入故意缩桥、堵门、让地板盖河、向船舱填水、删第二市场的反例，要求校验指出出错的实体。仅检查对象数量无法发现这些错误。[既有实网格检查](../experiments/3d-sample/verify_scene.py) · [石拱桥破坏测试](../tests/three-d/blender_arch_bridge_tamper.py)

**交互验收。** 在静态构建上通过正常按钮走完生成、导入、切换、旋转、缩放、复位、取消、换图、刷新和导出。解码 PNG 核对尺寸、非空内容与相机方向。覆盖 WebGL 不可用、缺失纹理、网络重试、高清导出失败以及连续切图十次。对单独打开二维页的网络请求断言三维脚本与 GLB 延迟加载。

**性能验收。** 下列为首轮拟定目标，M0 固定一台集显笔记本、一台中档 Android 和一台 iPhone，记录机型、浏览器、分辨率和像素比。以 10 Mbps、80 ms RTT 冷缓存测「点击三维到能转动完整基础城」，以相同 30 秒环绕路线测帧耗时。每组重复五次，报告首屏中位数及每次环绕的第 95 百分位帧耗时。冷、热缓存分开记录。

| 场景 | 建议目标 |
| --- | --- |
| M1 河城冷启动 | 集显笔记本 ≤5 秒，手机 ≤8 秒，基础场景可转动。首批新增三维压缩传输量目标 ≤3 MiB，选配细节另记 |
| M1 河城拖动 | 集显笔记本第 95 百分位帧耗时 ≤25 ms，中档手机 ≤33 ms。空闲时按需绘制 |
| M4 最大内陆城 | 2462 栋同时保留建筑几何。集显笔记本全景第 95 百分位 ≤33 ms，手机简化细节档 ≤50 ms。报告绘制调用、三角面、纹理和峰值资源数。连续换图后资源计数回到同一稳定区间 |

几何、交互、美术和性能分别记结果。对照截图固定机位、尺寸及色彩设置，另拍旋转过程检查线条闪烁。Playwright 验证功能，帧耗时在真机测量。每份结果附源图哈希、构建版本、素材版本与设备信息，便于区分代码回归和资产变更。

## 静态发布与回退

1. **构建。** 保留 Node 24、`npm run build` 和 `apps/playground/dist`。将 Three.js 的依赖版本和锁文件一起提交，静态构建产出带版本的素材清单、GLB 和必需纹理。CI 从干净检出执行 `npm ci` 和构建，再用 `npm run preview` 验证，构建过程中不读取开发机的 `artifacts/`。[项目构建脚本](../package.json) · [Netlify 配置文档](https://docs.netlify.com/build/configure-builds/file-based-configuration/)
2. **预览。** 先在 Netlify 预览部署中开放试点入口。阻断所有 `/api/3d/*` 请求后，生成或导入新城、查看、导出仍须通过。同时断言静态模式没有后台轮询。检查一份冷缓存和一份更新前缓存，避免新清单引用缺失资源。三维与原二维的构建和回归结果都纳入发布记录。
3. **切换与回退。** 完整验收通过后才将 Web 三维设为线上默认。保留上一份已验收的站点与匹配的资产清单。发布异常时整体回退。若仅个别浏览器不满足能力要求，保留二维和用户的规划快照。开发机继续提供旧 Blender 图片、任务历史与对照能力。

首版演示从一台没有本地三维服务的设备开始。打开预览网址，导入指定河城，沿街旋转到桥头，导出 1500 像素 PNG，并能用同一份规划和参考图复核屏幕上看到的桥、道路和两岸建筑。
