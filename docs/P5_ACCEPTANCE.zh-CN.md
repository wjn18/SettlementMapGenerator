# P5：绘制器对照与选型

日期：2026-09-30。SVG、Canvas 最小绘制器、并排页面、图像导出和评估已完成。用户已选择 Canvas 作为默认绘制器、SVG 用于矢量导出，P5 完成。core 算法及包版本仍为 0.4.0；map-scene、三个 renderer 和 playground 为 0.5.0。

## 可以直接观察的结果

运行 `npm run dev`，打开 [并排比较](http://127.0.0.1:5174/compare.html)。六个固定样本覆盖城堡小镇、城墙小城、无墙都会、城堡都会、密集街巷、无广场村落。三栏共享同一份 TownData / MapScene，联动平移、缩放和主题；不会为不同绘制器重新生成地图。

用户反馈正常缩放下难以看出差别后，增加了后三个样本、8× 缩放，以及“建筑与街巷 / 道路接合 / 城门与塔楼”细节镜头。“显示边缘差异”将 Canvas、SVG 的栅格图与 OpenFL 比较，把 RGB 通道差异放大 8 倍着色；白色表示相同。SVG 在该功能中由导出的 SVG 按当前 DPR 栅格化，屏幕子像素定位可能引入额外抗锯齿差异。差异图不是几何错误图，不表示某种绘制器必然更准确。

主预览默认 Canvas，显式 URL `renderer` 参数仍可选择其他实现。切换绘制器保持原地图、主题、视口与命中结果。独立的「导出 PNG」「导出 SVG」按钮分别使用 Canvas 和 SVG 绘制器导出当前视口，保留尺寸、背景与配色，不切换当前预览；临时绘制器在完成或失败后销毁。SVG 为独立矢量 XML，PNG 按当前 DPR 输出；仅导出地图，不包含页面控件、图名字体。JSON 保存功能保持原样。

## 测量范围与方法

原始数据见 [report.json](../tests/fixtures/p5/report.json)，固定输入及审查图见 [P5 证据](../tests/fixtures/p5/README.md)。性能矩阵使用前三个样本：3 个地图 × 3 个绘制器 × DPR 1/2 × 0.5×/1×/4×，共 54 组。后加的三个视觉样本和 8× 镜头接受功能检查，未混入这批性能数据。

Chrome 153.0.8010.53 / Windows，同一机器、800×800 CSS 像素。每组预热 3 次、重复 12 次；场景已经建立，计时不含算法生成、JSON 解析、字体或网络。首次显示计时包括创建绘制器、设置尺寸、提交场景和视口，前一次销毁在计时外。重绘与平移分别测量。

同步 API 的 CPU 时间和等待两个 requestAnimationFrame 的墙钟时间分别保存。OpenFL 把部分工作推迟到下一帧；SVG 样式布局/栅格化也可能延后，因此不能用 API 返回速度断言最终显示速度。两帧等待允许一次呈现机会，不是 GPU/compositor 计时，也不是精确输入延迟。下表展示无墙都会、1573 条指令、DPR=2、1× 的一次测量，中位/P95，单位 ms：

| 实现 | 首次显示 API | 重绘 API | 平移 API | 平移＋两帧等待 |
| --- | --- | --- | --- | --- |
| OpenFL | 10.5 / 11.2 | 0.9 / 1.1 | 0.3 / 0.4 | 33.4 / 33.5 |
| Canvas | 2.5 / 3.3 | 1.1 / 1.2 | 1.2 / 1.4 | 33.4 / 35.1 |
| SVG | 6.8 / 7.7 | 4.4 / 5.1 | 0.2 / 0.3 | 33.4 / 33.5 |

三者在此样本都能及时完成操作。Canvas 平移需要全量重绘；SVG 平移更新组 transform，但场景重建需要管理更多 DOM；OpenFL 有持续 RAF 和 GPU 状态管理。另对固定点执行 1000 次命中，平均约 6.3 / 2.7 / 2.8 微秒；共用几何语义，不比较不同算法。

## 图像、资源与依赖

54 张同视口图像已输出到 `artifacts/p5/`，其中 1× 的 18 张保存在仓库。Canvas/SVG 对 OpenFL 的 36 组像素比较中，最大平均 RGB 通道误差为 0.6804/255，最大“任一通道差异超过 16”的像素比例为 0.9125%。逐图观察道路双描边、城门、圆塔、城堡轮廓和建筑填充；差异主要集中在线条边缘。固定数据布局一致，不宣称逐像素完全相同。原 P3 旧地图截图继续通过。

独立 renderer 入口以 Vite 打包并包含实际绘制依赖，排除生成器/示例 UI 的通用成本：

| 实现 | JS 原始字节 | gzip 字节 | 输出与维护特点 |
| --- | ---: | ---: | --- |
| OpenFL | 1,618,590 | 298,570 | WebGL2，保留迁移参考，需要固定版本内部兼容处理 |
| Canvas | 3,678 | 1,672 | 一个画布，PNG，浏览器原生 API，无额外运行时 |
| SVG | 4,023 | 1,749 | path/circle DOM，独立矢量 XML，易于后续编辑 |

这些是本次构建的独立绘制入口，不是 npm 压缩包大小，也不是当前预览整页下载大小。预览和评估页面为了实时切换仍包含三种绘制器；本次切换默认值并未移除 OpenFL 依赖或实现按需加载，不能将独立 Canvas 入口大小视作整页体积。

三种绘制器在 DPR 1/2 下分别循环挂载/重绘/销毁 30 次。第 5 次到第 30 次强制 GC 后，JS 堆增量分别约 15–25 KB（OpenFL）、1.2 KB（Canvas）、1.3 KB（SVG）；各自 DOM 和监听器计数稳定。没有常驻 RAF 或自建监听器的是新 Canvas/SVG 适配器；页面交互监听器由应用管理。结果只说明有限循环稳定，不代表长期泄漏证明或 GPU 显存测量。

## 本次发现并修复的问题

第一次采样发现 OpenFL 重建后只剩背景。9.5.2 的静态默认 shader 对象持有旧 WebGL 上下文编译的 program，不能供新上下文使用。现在为每个 Stage 隔离 shader，释放时只清除该实例拥有的缓存。P4 资源计数检查没有验证每次重建后的图像内容，本次补上该回归：5 次重建后比较实际像素，要求平均通道差异小于 0.001，覆盖 DPR=2 的极少量抗锯齿变化，同时拒绝 WebGL INVALID_OPERATION。修复后的性能和截图重新采集，失败数据未纳入报告。
