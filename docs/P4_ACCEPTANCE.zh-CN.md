# P4：稳定性与库交付验收

日期：2026-09-30。core、map-scene、renderer-openfl 的包版本均为 `0.4.0`，算法版本为 `0.4.0`，数据格式仍为 `1`。P4 已完成，尚未发布到 npm。

## 算法与错误处理

旧 FIFO 寻路替换为 Dijkstra：按累计边长选择节点，相同代价按稳定节点 ID 排序，排除节点不可进入，断连返回 null；保持道路数据原有的终点到起点顺序。测试包括曾会过早选择昂贵路径的图、改善已发现路径、等价路径、零权环、断连、排除起终点，以及 30 张可复现随机图的 4320 个点对与独立 Floyd–Warshall 对照。最短性针对平滑前的拓扑边长，不承诺平滑后的道路仍是欧氏最短曲线。

这会改变部分相同种子的道路、街区和建筑。例如本机 Node 下 seed=42、size=24 的建筑数量由旧寻路的 866 变为 880。旧 `0.2.0-legacy` 地图应通过 JSON 保留，不能通过新版本同种子重新生成来恢复。旧 FIFO 仅保存在 `tests/core/legacy-path.mjs` 的历史对照工具中，不进入打包产物；P1 18 组完整阶段仍能在该工具中复现。当前算法单独验证，不宣称与旧算法逐字段一致。

620 组检查发现两个 Farm 建筑越界样本。导出现在检查建筑/特征顶点、边中点及穿越地块边界的线段，越界进入已有有限重试，跨重试资源预算仍累计。回归种子 `708675149/6` 和 `2147483646/6`（有广场、无城堡、有城墙）限制一次尝试时明确返回 `GENERATION_FAILED`、stage=`export`；默认预算分别在第 2、3 次成功。没有静默删除建筑或强行裁剪。

`INVALID_OPTIONS`、`GENERATION_FAILED`、`RESOURCE_LIMIT` 保持原有语义，程序异常继续抛出。覆盖塌缩多边形、非有限坐标、共线/倒序导入环、预算耗尽。TownData 格式未变，历史 JSON 仍可导入；导入校验是结构、数值和引用校验，不追溯应用新生成器的建筑包含规则。

## 浏览器响应与资源释放

playground 在模块 Worker 中生成，完成、异常、取消、替换请求和离开页面时终止 Worker；15 秒超时保留当前地图并允许重试。主题、缩放与平移仍在主线程。后发请求有优先权，旧结果不会覆盖新地图。使用真实无限循环 Worker 验证页面缩放仍响应，并通过受控时钟验证超时及恢复。

实际打包后的 renderer 在独立浏览器项目中，于 DPR 1/2 各挂载、重绘、销毁 40 次。每轮销毁后画布为 0，窗口监听器回到基线，待执行 RAF 为 0。预热 5 次后到第 40 次，强制 GC 的 JS 堆增量约 0.45 MB，低于 2 MB 验收上限；DOM 节点保持 32，事件监听器保持 34。记录见 [package-report.json](../tests/fixtures/p4/package-report.json)。数字包含浏览器测试工具自身监听器；这是有限循环的稳定性证据，不宣称长期运行绝无泄漏或测量了 GPU 显存。

P3 的版本兼容清理足以通过本次压力测试，未改变 OpenFL 绘制方式；OpenFL 固定 9.5.2，升级仍需重新验证内部回调和 DPR 接入点。
