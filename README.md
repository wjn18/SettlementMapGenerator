# SettlementMapGenerator

面向多个项目复用的城镇地图生成器，提供可直接使用的 Web 地图工坊，也可作为 TypeScript 算法库接入其他项目。当前已初步完成城镇生成，保留原项目的地图风格。

## 现有功能

| 功能 | 可以做什么 |
| --- | --- |
| 城镇生成 | 按种子生成地图，选择村落到都会的规模，配置城堡、广场和城墙，生成道路、街区与建筑。 |
| 河流、海岸与港城 | 支持河流、东南西北或自动方向的海岸，以及河口、桥梁、港区仓库和码头；港口可独立关闭。 |
| 地图浏览与配色 | 缩放、平移、悬停查看信息，切换图纸主题和街区分色；默认 Canvas 预览，也可切换 SVG / OpenFL，支持六组地图并排比较。 |
| 地名与区域 | 自动生成城市名与区域名，城堡和港区单独命名；可编辑中英文名称，并查看区域地块数、建筑数与用途。 |
| 地图辅助元素 | 独立开关网格、动态比例尺和八角罗盘；网格间距支持 25 / 50 / 100 / 200 米或自动。 |
| 人口估算 | 查看城区低 / 基准 / 高密度情景与区域分配，导出独立人口报告；城郊农地显示“未估算”。 |
| 保存、分享与导出 | 导入 / 导出地图 JSON，通过 URL 分享设置与地名，分别导出 PNG 图片和 SVG 矢量图，包含当前显示的地名及辅助元素。 |
| 算法库复用 | 在不依赖浏览器和 OpenFL 的环境中生成地图，通过 JSON 将实际几何交给其他工具或平台。 |
| 本地三维生成 | 将当前平面规划交给 Blender，生成线稿淡彩预览与高清图；支持进度、取消、历史结果及图片下载。 |

## 当前生成流程

当前统一规划算法版本为 `0.19.0`，二维规划是后续预览、导出和三维装配的统一数据源。教堂优先沿地块长轴安排主殿，再依据本地道路或相邻广场选择入口；远处市场不再主导建筑轴向。城门前的斜路采用相切曲线过渡，保留垂直门洞的直线喉道；共享路口和桥梁保持连接。塔楼按真实转角优先排布，并检查城堡/城市墙之间的间距，不再把密集的共线细分点全部变成塔楼。

1. **读取参数与种子**：校验规模、河海、城堡、广场和城墙开关，建立可复现随机序列与有限重试预算。
2. **道路骨架与地形**：建立弯曲贯通主路及错位支路，规划河流和海岸，预留干燥的城堡与广场位置。
3. **街区增长与防御范围**：沿道路细分土地并扩展城区，保留较早开发的核心；裁切水面，固定城墙包络，再规划墙内剩余陆地，保留公园、沿墙通道和部分墙外街区。
4. **街道与用途**：建立共享路口、普通街道、滨水路、桥梁和乡村连接，分配住宅、商业、手工业、军营、市场、公园、教堂及城堡等用途。
5. **门洞与道路调整**：城市门宽 8–20m，城堡门宽 6–12m；相邻门保持独立并保留至少 8m 实墙。入口避开墙角及城堡共墙连接点，道路用短过渡段转向，以接近垂直的方向穿门；必要时仅收窄城堡门前的短通道。新增路口共享顶点，新增道路避开水面，桥梁保留原几何。
6. **建筑与最终拓扑**：按用途生成建筑及公共要素，避让调整后的道路和墙体通道；城堡生成一个规整主建筑轮廓。教堂在现有地块内安排矩形主殿、方形钟楼和可选短翼，明确各体量角色；不沿三角地块围成细长连廊。导出实际门洞、墙段及塔楼；间距小于 24m 的城堡墙安全连接到城市城墙并共用墙段。再次检查门宽、独立性及至少 75° 的道路穿门夹角，不合格候选在预算内重试。
7. **二维显示与保存**：所有长度统一转为米，生成地名与人口估算，输出同一份 `TownData`；Canvas、SVG、OpenFL 和 JSON 均读取该几何，旧 JSON 保留原布局。
8. **三维装配与校验**：网页保存当前规划快照，适配器逐实体复制 ID、坐标及门洞，Blender 装配并保存普通房屋、专用石砌主堡、城墙、门楼和公共陈设。内陆单河按源实际河面裁出两岸陆地与河槽，按源桥位和宽度装配抬高的石拱桥、两端桥台和石护栏；桥头与两岸道路保持连接。沿海规划按源海面裁出陆地，沿岸线拼接护岸，按源路径与宽度拼装码头，为港区建筑安装仓储构件，并在通过避让检查的泊位停放三款船。河口城市使用同一份水陆分区，海面与河面衔接且不重叠，河口不生成封堵护岸；支持四向海岸与港口开关。先核对实际网格占地、墙段覆盖、门口通行、水陆分离、桥梁、码头及船只，通过后默认只渲染城内图；全景与城堡图按需生成。同一规划、依赖版本及文件哈希匹配时复用结果或场景。多个市场按来源 ID 分别装配和校验，并共享人物与道具避让。

## 快速开始

### 启动地图工坊

需要 **Node.js >= 22.12.0**；已验证 Node.js 24.19.0 / npm 11.17.0.

以下命令均在 **`SettlementMapGenerator/` 目录（本 README 所在目录）**运行。

```sh
npm ci --cache .cache/npm
npm run dev
```

打开 [城镇地图工坊](http://127.0.0.1:5174)，即可开始生成地图。

### 从网页生成三维

本机需安装 Blender（当前验证版本 5.2）；默认查找 `C:/Program Files/Blender Foundation/Blender 5.2/blender.exe`，其他安装位置请在启动服务前设置 `BLENDER_PATH`。

1. 生成或导入一张内陆、沿河、沿海或河口平面图。可先打开[内陆河城示例](http://127.0.0.1:5174/?seed=7&size=12&coast=false&river=true&walls=true&castle=false&plaza=true)、[沿海港城示例](http://127.0.0.1:5174/?seed=7&size=6&coast=east&harbor=true&river=false&walls=false&castle=false&plaza=true)或[河口港城示例](http://127.0.0.1:5174/?seed=7&size=12&coast=east&harbor=true&river=true&walls=true&castle=false&plaza=true)。海岸支持四个方向，港口可以关闭。
2. 在左侧「三维场景」选择快速预览（1500 px）或高清（3200 px），点击「生成当前地图的 3D」。未点击「生成地图」的参数修改不会混入当前规划。
3. 上方「平面规划 / 三维效果」切换视图。默认只生成「城内放大」，选择「完整全景 / 城堡局部」会复用模型并按需生成该图。相同规划再次生成同质量、同取景时，直接复用已完成结果。三维页显示真实任务阶段，可以取消；刷新页面后任务与历史仍可找回。
4. 完成并通过结构校验后，可查看原图或下载当前取景的 PNG 图片。三维文件接口只公开渲染图片，模型、规划快照及校验和耗时报告保存在后台，用于渲染、缓存和重试。历史结果来自其他规划时有明确提示。

沿海规划会自动使用新增海水、护岸、码头、仓库构件及三款船，无需手工导入。船舱内的海面、浅水和涟漪会按船体截面裁掉，并校验连续木质舱底。

内陆单河使用自然岸剖面、护岸收口和按源跨距生成的石拱桥；弧形桥面、拱券、石护栏与两端桥台共同保持道路连接。水边界、桥位和道路净宽来自同一份二维规划。新增内河港口使用共享港口库与无桅货船：二维保存顺岸码头、装卸留空、泊位和进出水路，三维按源位置装配并处理船舱排水。新版河港使用加宽码头，将无桅货船恢复到 0.17.0 尺寸，与新增三款货运帆船混合停泊；同步预留安全水路与船底净空。石拱桥检查实际桥下开口；港口仍只使用连通河流端部的河段，船舶运动属于后续扩展。见[内河港口说明](docs/RIVER_HARBOR_IMPLEMENTATION.zh-CN.md)与[河流素材文档](experiments/3d-sample/river-assets.md)。

网页选择「河流」后可独立开启「内河港口」。[内陆河港示例](http://127.0.0.1:5174/?seed=7&size=12&river=true&riverHarbor=true&coast=false&walls=false&castle=false&plaza=true)与[河口双港示例](http://127.0.0.1:5174/?seed=7&size=24&river=true&riverHarbor=true&coast=east&harbor=true&walls=false&castle=false&plaza=true)分别对应三维历史中的「内陆河港样片」和「河口双港样片」。命令行新增 `--river-harbor true`；原有 `--harbor` 继续只控制海港。

河口城市复用河流与港口素材，按源河面和海面的实际交点生成两岸与海岸。河流进入海面的部分只保留一层可见水面，海岸护岸在河口处留开口；码头、仓储构件和船只沿用原港口规则。船舱排水检查覆盖海面、河面及浅水和水纹层。独立校验同时检查源河、海区域覆盖、无叠水、河口开放和桥头通行。

护岸在码头入口处保留下部挡墙、降低上部压顶，使木板与岸边道路齐平通过；校验会检查整幅通行宽度。三维道路保留源中心线与宽度，在转弯外侧增加圆弧连接面，合并同一道路的铺装范围并剔除重叠面，避免弯道接缝出现阴影条纹；共享路口补齐铺装。旧 JSON 保留原中心线；重新生成地图后应用 0.15.0 的曲线规划。旧 JSON 中冗余塔楼候选点的筛选记录在三维适配数据里，原始规划文件不变。

命令行也可直接配置内陆河流、海岸、河口与港口：

```sh
npm run sample:3d -- --seed 7 --size 6 --coast east --harbor true --river false --walls false --castle false --plaza true --preview --output artifacts/harbor-town --name scene
npm run sample:3d -- --seed 7 --size 12 --coast false --river true --walls true --castle false --plaza true --preview --output artifacts/3d-river-town --name scene
npm run sample:3d -- --seed 7 --size 12 --coast east --river true --harbor true --walls true --castle false --plaza true --output artifacts/3d-estuary-town --name scene --resolution 3200
```

`--coast` 支持 `east / south / west / north / auto / false`；`--harbor`、`--river` 使用 `true / false`。`--walls`、`--castle`、`--plaza` 另支持 `auto`。导入 JSON 时使用 `--input`，不再同时指定这些规划参数，以保留原图几何。

缓存同时核对规划、几何代码、校验代码、渲染代码、美术库以及产物的实际字节哈希；图片还会检查质量与分辨率。修改模型、素材或代码后，不会盲目复用旧结果。快速预览保留完整可编辑模型，以 1500px / 24 采样渲染当前取景，首次仍需拼装模型；切换清晰度可直接复用已有模型。

已保存三维场景的失败任务会显示「复用已保存场景重试」。素材版本一致时保留场景，修复裁切屋顶并重新校验，再继续渲染；素材库、港口截面数据或船舱排水规则已更新时，会保留同一份原规划并用当前素材重新装配。原失败记录仍保留。未保存场景的任务继续使用左侧生成按钮。

当前网页展示轴测渲染图，仅提供图片下载。专用建筑仍有通用模型占位；三维水面为静态淡彩效果，支持内陆单河、石拱桥、沿海港城和河口城市，支持多个市场的逐广场装配和校验。已有村落、小镇、港城与河口样片会自动加入历史列表。港口素材与装配说明见[沿海素材文档](experiments/3d-sample/harbor-assets.md)。

河流定居点的全规模回归覆盖 6、12、24、40、60、80、100 七档，各有内陆河和河口港城样片。完整场景、结构报告和成图入口为 `artifacts/river-all-sizes/index.html`，范围、道路裂缝修复及复现命令见[全规模回归说明](docs/RIVER_CITY_IMPLEMENTATION.zh-CN.md#全规模回归)。

三维接口由本地 `npm run dev` 服务提供，只监听本机、同一时间执行一个任务；纯静态构建或 `npm run preview` 不含 Blender 后端。任务和输出保存在 `artifacts/web-3d/<任务ID>/`。网页流程验收命令：服务启动后运行 `node tests/three-d/web-integration.mjs`（会实际生成一次预览并验证取消任务）。

河流网页流程可运行 `node tests/three-d/river-web.mjs --base http://127.0.0.1:5174`，会导入 `artifacts/3d-river-town/source-town.json` 并提交当前规划。已生成样片后，可运行 `node tests/three-d/river-web.mjs --reuse-sample`，在独立服务和任务目录中验证真实提交、缓存复用、后台河流结构报告、图片下载及模型下载拒绝，无需重复渲染。

河口网页流程使用 `node tests/three-d/estuary-web.mjs --reuse-sample --port 5175`，默认读取 `artifacts/3d-estuary-town/` 的已验证样片，实际提交原规划并检查河口、河流、港口报告及下载。也可用 `--base http://127.0.0.1:5174` 验证实际生成；未指定 `--base` 时使用独立任务目录和临时服务，结束后关闭。

### 生成、调整与保存

左侧通过「城镇生成 / 三维场景 / 人口估算 / 文件导出」切换任务，切换时保留已填写的参数。生成页底部固定「生成地图」按钮；绘制方式与并排比较收在「高级工具」，JSON 档案与 PNG / SVG 图片集中在「文件导出」。桌面可收起侧栏扩大地图，窄屏下参数区可独立滚动。

1. 调整种子、规模，以及河流、海岸、城堡、广场和城墙等选项，生成地图。生成在后台执行，显示当前尝试次数和已完成阶段，可随时取消。持续推进的任务不会因总耗时超过 15 秒被中断；无进度时小城镇等待 15 秒、大于 40 地块的城市等待 30 秒，单次生成总上限为 120 秒。取消、失败或超时保留当前地图。
2. 滚轮缩放、拖动平移，悬停查看区域和街区信息。键盘方向键移动，`+` / `-` 缩放，`0` 复位。
3. 切换图纸主题；关闭「街区分色」可查看统一建筑配色。网格、比例尺和罗盘可在地图上方独立开关。
4. 点击地图选择区域，或点击右上角「编辑地名」，修改中英文名称。改名和切换人口情景均不会重新生成布局。
5. 使用独立的 PNG / SVG 按钮导出图片，或导出 JSON 保存地图。之后导入 JSON 可保留原始几何。

规模支持 **6–100 个基础城区地块**，预览提供以下档位：

| 村落 | 小镇 | 大镇 | 小城 | 中城 | 大城 | 都会 |
| --- | --- | --- | --- | --- | --- | --- |
| 6 | 12 | 24 | 40 | 60 | 80 | 100 |

数字表示基础地块数，墙内补建、城堡与水域裁切可能改变最终数量，实际值见「本次生成」。旧 URL / JSON 的其他合法规模仍可作为自定档位使用。

启动后可直接打开[河口港城示例](http://127.0.0.1:5174/?seed=42&size=24&coast=east&river=true&harbor=true&castle=true&plaza=true&walls=false&theme=modern&districts=false)。

常用 URL 参数：

| 参数 | 用途 |
| --- | --- |
| `seed`、`size` | 设置种子与基础城区地块数。 |
| `coast`、`river`、`harbor` | 配置海岸、河流与港口；示例使用 `coast=east&river=true&harbor=true`。 |
| `castle`、`plaza`、`walls` | 配置城堡、广场与城墙。 |
| `theme`、`districts`、`labels` | 设置主题、街区分色与地名显示，例如 `theme=modern&districts=false&labels=false`。 |
| `grid`、`scale`、`compass`、`gridSize` | 保留网格、比例尺、罗盘和网格间距设置。 |
| `population` | 选择人口情景：`sparse` / `typical` / `dense`，默认 `typical`。 |

算法升级可能改变同一 seed 的地图布局。需要保留某张地图，或在不同运行环境间传递同一布局时，请保存并导入 JSON。

## 调用算法库

完成依赖安装后，在本目录构建算法库：

```sh
npm run build:core
```

工作区可直接导入 `@settlement/core`；当前尚未发布 npm 包。

```ts
import { generateTown, serializeTown } from '@settlement/core';

const result = generateTown({ seed: 12345, size: 24 });

if (result.ok) {
  console.log(serializeTown(result.town));
} else {
  console.error(result.error);
}
```

也可通过命令行生成 JSON：

```sh
node scripts/generate-town.mjs 12345 24 town.json
```

完整 API 与数据说明见 [core 文档](packages/core/README.md)，独立项目接入与打包示例见 [examples](examples/README.md)。

## 技术实现

### 模块架构与数据

采用 **TypeScript 算法库 → 独立绘制指令 → Canvas / SVG / OpenFL 绘制器**的分层结构。当前统一规划算法版本为 `0.19.0`，绘制层版本为 `0.5.0`。

| 模块 | 职责与文档 |
| --- | --- |
| `packages/core` | [生成算法与地图数据](packages/core/README.md)，不加载 OpenFL、DOM 或浏览器窗口。 |
| `packages/map-scene` | [独立绘制指令](packages/map-scene/README.md)，提供主题、地名与地图辅助元素的共享布局。 |
| `packages/renderer-canvas` | [Canvas 绘制器](packages/renderer-canvas/README.md)，用于默认预览。 |
| `packages/renderer-svg` | [SVG 绘制器](packages/renderer-svg/README.md)，用于矢量绘制与导出。 |
| `packages/renderer-openfl` | [OpenFL 适配层](packages/renderer-openfl/README.md)，保留作迁移对照。 |
| `apps/playground` | Web 地图工坊，在 Worker 中执行生成，提供交互、比较与导出。 |

预览、三种绘制器、PNG / SVG 与 JSON 共用实际几何。JSON 使用共享顶点 ID，可交给其他工具和平台。复现保证限于相同算法版本、输入和 JS 运行环境；跨 Node / Chrome 保持同一张地图时传递 JSON。旧地图可通过 JSON 原样导入，重新生成才会使用新算法。

### 道路引导生长与地形

算法 `0.11.0` 先预留弯曲的贯通道路和错位接入的支路，再沿道路方向细分可开发土地，从多个活动中心附近连续扩展城区。增长按道路距离、中心距离和相邻开发情况选择地块，外围保留凹入空地与沿路延伸，不再填满固定放射扇区或六边形外圈。

水域先裁出可建设陆地，再规划沿岸道路、桥梁和街区建筑；裁切后补足请求的陆地地块数。岸边路口优先作为桥头，并补齐街道片段之间必要的陆地连接。河流与海岸组合生成河口，港区沿岸生成仓储建筑与码头。

开放街区建筑靠近道路，背街逐渐留空，默认绘制不铺整块底色。主路约 15.2 m、支路与沿岸道路至少 10.4 m、普通街道 5.6 m，建筑避让道路和桥头。全部长度按规划坐标的 4 倍导出为米；导出后默认 1 地图单位 = 1 米，比例尺和人口计算不再叠加倍率。这是设计尺度，不是历史测绘校准。

40 以上的城市保留有限生成预算，默认最多重试 40 次；较小规模默认 20 次。

### 城墙、城堡与墙内用地

街区增长后，在生成街道、用途和建筑之前，固定核心城区与城堡的紧凑城墙包络。城墙围绕较早开发的核心区，较晚街区可在墙外。沿墙裁分原有乡野地块，较大的可建空间继续细分并接入街道，狭窄或零碎部分作为绿地；墙外保留乡野与沿路城郊。

建筑生成时预留沿墙通道，最后导出仅补齐塔楼、城门开口与道路连接，不再重新扩大墙线或删除建筑。墙内补建会增加实际城区地块数，规模选项仍表示基础地块数。人口只对已转为城区的陆地按既定密度公式估算，水面和墙外乡野不计入城区。

城堡合并为单栋建筑，并筛除过于不规则的轮廓。三种绘制器和 JSON 共用最终几何；旧 JSON 保留原图，重新生成后使用新城堡。

### 地名与地图辅助元素

相邻城区地块归为命名区域，城堡与港区单独命名。曲线地名随视口排版，避开水面、桥梁及其他标签，缩小时隐藏过密文字。地名随 JSON 和分享 URL 保存，PNG / SVG 导出包含当前显示的地名。旧版 JSON 自动补充显示名称，首次改名才写入命名数据。

网格、动态比例尺和八角罗盘在 Canvas / SVG / OpenFL 与 PNG / SVG 导出中共用布局。网格固定在地图坐标上，缩小到过密时按整倍数合并，并显示实际间距；比例尺按当前缩放选择整齐的距离刻度，自动使用 m / km；罗盘始终朝北。默认 1 地图单位 = 1 米的显示约定不改变城市几何。URL 保留辅助元素的显示设置，地图 JSON 继续保存城市数据。

### 人口估算口径

城区常住人口按 **城区用地公顷数 × 人口密度**计算。低 / 基准 / 高情景为 50 / 100 / 200 人/公顷，默认基准情景；人/栋仅用于对照。系数参考 [Buringh (2021), p. 8](https://researchdatajournal.org/article/download/24674/25863/63436) 的中世纪欧洲城市面积代理值，低、高情景不是统计置信区间。

用城区地块面积合计近似已居住城市用地，包含其中的道路、院落、市场和公园，当前生成地图的地块已裁去河海；默认 1 地图单位 = 1 米，尺度与城区范围未经历史校准。城郊农地不适用城市密度，明确显示“未估算”。

区域人数按城区建筑占地比例分配，市场、公园和装饰不参与分配。建筑仅影响分配，不影响总人口，不使用贫富街区人均面积、楼层或入住率系数。没有可分配建筑时，城区总估值保留，并显示未分配人数。

调整情景不改变地图布局，界面、悬停、区域详情及独立人口报告 JSON 同步。报告含文献、面积口径和假设，地图 JSON 保持不变。

## 开发与验证

```sh
npm run build

```

### 从 GitHub 部署到 Netlify

在 Netlify 中连接 `wjn18/SettlementMapGenerator` 仓库，生产分支选择 `main`。仓库根目录的 `netlify.toml` 指定 Node.js 24、构建命令 `npm run build` 和发布目录 `apps/playground/dist`；安装依赖与构建均从仓库根目录执行。连接后，推送到 `main` 会自动触发构建和发布。

线上站点提供二维地图生成、三种绘制器、并排比较、保存分享和导出。Blender 三维任务仍需本机 `npm run dev` 服务；静态站点会显示本地三维服务不可用，并禁用三维生成按钮。
